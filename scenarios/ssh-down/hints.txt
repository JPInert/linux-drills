Is sshd even running? Nothing is listening on port 22, so it is not the network. Ask systemd what state the ssh service is in and which step of starting it failed (systemctl status ssh).
Before sshd starts, systemd runs a config test, and that test is what fails. The ssh journal shows what the test said, and `sudo sshd -t` runs the same test by hand and prints the exact file and line number.
`sudo journalctl -u ssh -n 20` (-u = this unit, -n 20 = last 20 lines), then `sudo sshd -t` (-t = test the config only). Fix the one misspelled word on that line with `sudo nano /etc/ssh/sshd_config` (do NOT delete the line: the auditors need it), run `sudo sshd -t` again until it prints nothing, then `sudo systemctl start ssh` and `sudo ss -tlnp | grep :22` (t = TCP, l = listening, n = numbers, p = program).
