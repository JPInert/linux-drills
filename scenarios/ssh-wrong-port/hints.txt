"Connection refused" means the box answered, but nothing was listening on that port, so it is not the network. Ask the box two things: is sshd running at all, and which port is it really listening on?
`sudo ss -tlnp | grep sshd` shows the port sshd is really on (-t TCP, -l listening, -n numbers not names, -p which program). `sudo sshd -T | grep -i port` shows the port sshd's config asks for (-T = print the config sshd would use, after reading every file it includes).
`grep -ri port /etc/ssh/sshd_config*` finds the file with the wrong Port line (-r = look inside the .d folder too, -i = any upper/lower case). Fix that one line with `sudo nano FILE`, run `sudo sshd -t` (no output = config is valid), then `sudo systemctl restart ssh` and prove it with `nc -zv localhost 22` (-z = just connect, send nothing; -v = say what happened).
