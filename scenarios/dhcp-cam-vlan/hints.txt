Old cameras with fixed IPs work and only the new DHCP ones fail: the WiFi carries traffic fine, so look at the DHCP SERVER on this box, and at what it says when a camera asks.
`systemctl status dnsmasq` (the DHCP server here) and `sudo journalctl -u dnsmasq | tail` (-u = this unit's log): "no address range available for DHCP request via eth1" means a request arrived on eth1 but no configured range fits eth1's subnet. Compare `ip a show eth1` with the dhcp-range in the config.
`cat /etc/dnsmasq.d/cam-wifi.conf` and `cat ~/install-sheet.txt`: fix EVERY address that belongs to another site with `sudo nano /etc/dnsmasq.d/cam-wifi.conf`, check it with `sudo dnsmasq --test`, apply with `sudo systemctl restart dnsmasq`, then `sudo journalctl -u dnsmasq | grep DHCPACK` (grep = only lines containing DHCPACK) and `cat /var/lib/misc/dnsmasq.leases`.
