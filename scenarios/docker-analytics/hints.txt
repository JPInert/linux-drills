The detector is up but slow while the video is smooth, so it is not the network: find out whether the vehicle-count container runs its model on the GPU or on the CPU. Ask the GPU who is using it, and ask the container what it said when it started.
Run `nvidia-smi` (is ANY process on the GPU?), `sudo docker ps` (what is running), and `sudo docker logs vehicle-count | head` (its first lines, from start-up). Then check whether the container was given a GPU at all: `sudo docker inspect vehicle-count | grep DeviceRequests` (null = no GPU was asked for). The update left the old compose file next to the new one: `ls /opt/vehicle-count`, then diff them.
`diff OLD NEW` shows what the update dropped. Copy the deploy: block (driver: nvidia, count: all, capabilities: [gpu]) back into the vehicle-count service with `sudo nano /opt/vehicle-count/compose.yaml`, then `cd /opt/vehicle-count` and `sudo docker compose up -d` (-d = run in the background). A plain restart does NOT re-read the file; `up -d` rebuilds the container from it.
