Right address, link UP, and still nothing answers on the camera network: when the box can't even find a camera's MAC address, look at layer 2. On a trunk that means the VLAN tag the box puts on its frames.
`ip neigh` (the box's ARP table: FAILED/INCOMPLETE = nobody answered "who has this IP?"). An interface NAME like eth1.50 is only a label: `ip -d link show eth1.50` (-d = details) prints the VLAN id it really tags with; compare it with the install sheet. `sudo tcpdump -eni eth1 -c 3` (-e = show the link header incl. the vlan tag, -n = no name lookups, -i = this interface, -c 3 = stop after 3 packets) shows it on the wire.
`networkctl status eth1.50` names the files; the id is in /etc/systemd/network/20-eth1.50.netdev. Fix Id= there with `sudo nano`, then `sudo ip link delete eth1.50` (networkd never changes the id of an existing VLAN link) and `sudo systemctl restart systemd-networkd` to rebuild it; prove it with `ip -d link show eth1.50`, `ping -c 3 10.50.50.31` and the recorder's journal.
