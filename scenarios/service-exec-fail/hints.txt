The service fails the instant it starts, so the program itself never really ran. Read systemd's verdict: `systemctl status feedrelay` shows a status= code, and the unit's journal says which step broke.
There are two problems, one after the other. First the script's permission bits (look at it with ls -l), then a folder named in the unit file that does not exist. Read the status again after each fix: the code changes. Systemd does not notice edits to a unit file until you tell it.
`sudo journalctl -u feedrelay -n 20` (-u = this unit, -n 20 = last 20 lines); `sudo chmod 755 /opt/feedrelay/bin/run.sh` (adds the x = execute bit); `systemctl cat feedrelay` shows WorkingDirectory=; `ls /opt/feedrelay` shows what really exists; fix that line with `sudo nano /etc/systemd/system/feedrelay.service`; then `sudo systemctl daemon-reload` (re-read unit files) and `sudo systemctl restart feedrelay`.
