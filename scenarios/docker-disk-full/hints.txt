It is a disk problem, but on which filesystem? Find the one at 100%, then split what fills it into images (old versions, dangling layers) and container logs, and ask why a log can grow forever.
df / du for the filesystem, then Docker's own view: docker system df, docker images, and the log settings a container was created with (docker inspect ... LogConfig). Log limits live in /etc/docker/daemon.json or the compose file.
`df -h` (-h = human sizes), `sudo du -h -d1 /var/lib/docker` (-d1 = one level deep; `sudo du .../*` fails because YOUR shell can't list the dir), `sudo docker system df`, `sudo docker images`, `sudo docker inspect event-uploader | grep -A3 LogConfig`; free with `sudo docker image prune` (dangling only) and `sudo docker rmi` the two oldest tags (NOT 2.4.0), add "log-opts" max-size/max-file to daemon.json, `sudo systemctl restart docker`, then `sudo docker compose up -d --force-recreate` in /opt/edge (limits only apply to NEW containers).
