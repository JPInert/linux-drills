The camera answers ping and its web page, so the path to it is up. Ask the recorder exactly what fails (which address, which port), then test that same port from this box.
`sudo journalctl -u nvr-recorder | tail` (-u = only this unit's log) names the address and port. `nc -zv -w 3 10.50.1.31 554` (-z = connect only, -v = say what happened, -w 3 = give up after 3 s): a TIMEOUT on one port while ping and port 80 work means something silently drops that port, and on this box that is its own firewall.
`sudo iptables -L -n -v` (-L = list the rules, -n = numbers not names, -v = packet counters): follow OUTPUT into its camera chain and find the DROP whose counter climbs. `systemctl status netfilter-persistent` loads /etc/iptables/rules.v4 at boot: delete only that line with `sudo nano /etc/iptables/rules.v4`, test with `sudo iptables-restore --test /etc/iptables/rules.v4`, load with `sudo systemctl restart netfilter-persistent`, then read the recorder's journal again.
