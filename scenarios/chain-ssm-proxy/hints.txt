The agent is running but can't reach AWS: find out how this site lets web traffic out now, then check whether the agent's own process was ever told.
Compare your shell with the service: the agent's log file, the site notes in your home dir, `env | grep -i proxy`, and what the agent printed about its proxy when it started (its journal).
`sudo tail -20 /var/log/amazon/ssm/amazon-ssm-agent.log` (-20 = last 20 lines), `cat ~/SITE-NOTES.txt`, `sudo journalctl -u amazon-ssm-agent | grep -i proxy` (-u = this unit only; https_proxy: empty = it has none). Services never read /etc/environment: `sudo systemctl edit amazon-ssm-agent` opens a drop-in (arrow down to the empty line, type [Service] + Environment="https_proxy=..." lines), then `sudo systemctl restart amazon-ssm-agent`.
